# Проверка решения

Отдельных критериев начисления баллов в исходном PDF нет. Обязательны React, простой интерфейс мессенджера (выбран разрешённый вариант WhatsApp), вход с данными GREEN-API, новый чат по номеру, отправка и получение текста. Ниже — сценарии приёмки и ориентиры качества.

## Обязательный сценарий на реальном API

1. Выполнить `npm ci` и `npm run dev` по README.
2. Авторизовать инстанс WhatsApp в GREEN-API и настроить HTTP-уведомления.
3. Ввести данные в форму. Убедиться, что открылась область чатов.
4. Создать диалог по номеру второго аккаунта WhatsApp.
5. Отправить «Привет» и проверить получение в приложении WhatsApp получателя.
6. Ответить из WhatsApp и убедиться, что ответ появился в том же диалоге браузера.
7. Создать второй чат, переключиться и проверить раздельное отображение сообщений.

Эти шаги требуют реальных аккаунтов. Автоматические тесты и локальный стенд не заменяют проверку доставки.

## Что оценивать в коде

| Область           | Признак качественного решения                                                           |
| ----------------- | --------------------------------------------------------------------------------------- |
| Выполнение задачи | Работает полный путь «ввод ключей → чат → сообщение → ответ»                            |
| Работа с API      | Верные методы, `chatId`, последовательный опрос и подтверждение receiptId               |
| Асинхронность     | Отмена при выходе, отсутствие двух циклов, backoff при сетевой ошибке                   |
| Состояние         | Ответы не дублируются, чаты не смешиваются, статусы не откатываются                     |
| Ошибки            | Понятные сообщения, отсутствие бесконечной загрузки и автоматической повторной отправки |
| Интерфейс         | Узнаваемая структура мессенджера, адаптация для телефона, клавиатура, пустые состояния  |
| Структура         | UI, API и управление состоянием разделены, TypeScript strict                            |
| Секреты           | Реальных токенов в исходниках нет, произвольные API-хосты отклоняются                   |
| Воспроизводимость | Зафиксированные зависимости, команды запуска/сборки, понятные ограничения               |

## Негативные сценарии

- Неверный ключ: вход завершается ошибкой, форма остаётся доступной.
- Инстанс не авторизован: показана инструкция, чат не открывается.
- Неверные настройки webhook: вход объясняет, что изменить в кабинете.
- Некорректный номер или отсутствующий аккаунт: диалог не создаётся.
- Пустое сообщение/более 20000 символов: отправка недоступна.
- Временный сетевой сбой: сообщение об ошибке; опрос восстанавливается с паузой.
- Ошибка отправки: текст остаётся в истории со статусом ошибки, его можно вернуть в редактор.
- Повтор уведомления: нет второй копии сообщения или лишнего непрочитанного.
- Выход: возвращение к форме, сетевые запросы отменены, ключ и чаты удалены из памяти.
- Две вкладки с одним инстансом: вторая сообщает о занятом подключении (при поддержке Web Locks).
- Узкий экран: список и переписка отображаются поочерёдно, есть кнопка назад, нет горизонтальной прокрутки.

## Выполненная проверка

- Production-сборка и TypeScript strict.
- 19 автоматических тестов API, reducer и цикла опроса.
- Для ручной проверки интерфейса предусмотрен локальный стенд с имитацией API.

Реальная доставка в WhatsApp не проверена без пользовательского инстанса. Это открытый пункт приёмки, а не подтверждённый результат.
