# Пульс — чат для MAX

React-приложение для отправки и получения текстовых сообщений в MAX через GREEN-API. Интерфейс вдохновлён веб-версией MAX: список диалогов, область переписки, входящие и исходящие сообщения. Минимальный интерфейс: форма входа, список чатов, переписка и поле отправки. Собственная сдержанная палитра; без промоблоков, поиска, выбора эмодзи и панели информации о чате. Это неофициальный клиент.

## Запуск

Требуется Node.js **22.12 или новее** и npm. Установите зависимости и запустите приложение:

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173).

```sh
npm run build   # проверка TypeScript и production-сборка в dist/
npm run preview # локальный просмотр production-сборки
npm test        # автоматические проверки логики и API
```

Для публикации на статическом хостинге загрузите содержимое `dist/`. Серверная часть и переменные окружения не нужны. Ключи нельзя добавлять в код или `.env` с префиксом `VITE_`.

## Подготовка GREEN-API

1. Создайте **инстанс MAX** в [кабинете GREEN-API](https://console.green-api.com/) и авторизуйте аккаунт MAX. Состояние должно быть `authorized`.
2. В настройках инстанса включите **«Получать уведомления о входящих сообщениях и файлах»** (`incomingWebhook: yes`).
3. Оставьте **Webhook URL пустым** — приложение использует HTTP API. Не подключайте к той же очереди другого потребителя. Изменения настроек могут применяться около минуты.
4. При необходимости включите уведомления о статусах исходящих сообщений (`outgoingWebhook: yes`), чтобы видеть доставку и прочтение. Без них сообщение имеет статус «Принято GREEN-API».
5. Скопируйте `idInstance`, `apiTokenInstance` и **apiUrl именно вашего инстанса** в форму входа. Адрес сервера нельзя надёжно угадывать по номеру инстанса, поэтому он вводится отдельным полем.
6. Нажмите «Войти», затем «Новый чат», введите номер получателя и напишите сообщение.
7. Ответьте с аккаунта получателя в MAX — ответ появится в том же диалоге.

Приложение проверяет состояние и настройки при входе, но не изменяет настройки инстанса автоматически. Для проверки реального обмена нужны ваш инстанс, доступный тариф и второй аккаунт MAX. Поиск получателя по номеру может быть ограничен его настройками приватности.

## Поведение приложения

- Несколько чатов, счётчики непрочитанных и отдельные черновики.
- Enter для отправки, Shift + Enter для переноса строки, поддержка emoji, введённых с клавиатуры.
- Проверка пустого текста и ограничения 4000 символов.
- Статусы «Отправляется», «Принято GREEN-API», «Доставлено», «Прочитано», ошибка/неопределённая отправка.
- Автоматическое восстановление опроса после временных ошибок с увеличением паузы до 30 секунд.
- Отмена запросов при выходе, отсутствие параллельных циклов опроса; Web Locks защищает от двух вкладок одного сайта, читающих один инстанс.
- Нативные доступные диалоги с Escape, возвратом фокуса и управлением с клавиатуры.
- Поддержка экспериментального WebMCP: `start_new_chat` только открывает форму, не отправляет сообщений.

## Архитектура

```text
src/
  components/        # Вход, окно мессенджера, доступный диалог
  hooks/             # useMessenger: жизненный цикл подключения и действия
  lib/api.ts         # GREEN-API, нормализация ввода, безопасные ошибки
  lib/chat-state.ts  # Чистый reducer: диалоги, сообщения, статусы, дедупликация
  lib/polling.ts     # Последовательный опрос, подтверждения, backoff, отмена
  lib/webmcp.ts      # Необязательная интеграция с браузером
  types.ts           # Типы приложения и используемых событий API
tests/
  harness.html       # Локальный стенд с имитацией API; не входит в сборку
docs/
  REVIEW.md          # Требования, критерии качества и ручная проверка
```

Глобальная библиотека состояния не нужна для такого объёма: чистый `useReducer` управляет данными, хук отделяет сеть от интерфейса. Отправленные сообщения появляются сразу; статус обновляется после ответа API. События статусов, пришедшие раньше ответа отправки, временно сохраняются и затем применяются.

Получение работает через long polling. Уведомление подтверждается после передачи в состояние. Повторная доставка безопасна благодаря проверке `idMessage`. Уведомления о медиа, группах и другие неподдерживаемые типы обрабатываются как пропущенные и также подтверждаются, чтобы очередь продолжала двигаться. Для использования этой очереди другими приложениями нужен отдельный инстанс.

## Данные и ограничения

- Ключ и переписка находятся **только в памяти текущей вкладки**. Они не сохраняются в localStorage/sessionStorage, URL страницы или репозитории. Выход/обновление страницы очищает сессию.
- После обновления исторические сообщения повторно не загружаются. Полная история остаётся в MAX. Постоянное хранение и загрузка истории не требуются исходным заданием.
- Приложение обращается из браузера напрямую к HTTPS-серверу GREEN-API. Ключ присутствует в URL запросов согласно протоколу сервиса и доступен владельцу браузера в DevTools. Серверы для отправки ключа ограничены доменом `green-api.com`.
- При сетевом таймауте отправка может фактически состояться. Поэтому приложение не отправляет сообщение повторно автоматически, а предлагает проверить MAX и вручную вернуть текст в поле ввода.
- Отправка/получение файлов, группы, звонки, редактирование и удаление сообщений намеренно не входят в задачу.
- Поиск по номеру рассчитан на РФ и Беларусь согласно документации `CheckAccount`. Настройки приватности и тарифные лимиты контролирует GREEN-API/MAX.
- Если Web Locks недоступен, используйте одну вкладку на инстанс. Даже при Web Locks другая программа или браузер могут конкурировать за очередь.

## Проверка без реальных ключей

Во время `npm run dev` откройте **http://127.0.0.1:5173/tests/harness.html**. Это отдельный локальный стенд: вызовы GREEN-API подменены, реальные сообщения не отправляются. Введите:

```text
idInstance:       3100000001
apiTokenInstance: test-token-only
apiUrl:           https://3100.api.green-api.com
Номер получателя: +7 999 123-45-67
```

На любой отправленный текст придёт тестовый ответ. Текст `Ошибка` имитирует HTTP 500. Ключ `invalid-token-test` имитирует неверную авторизацию. Номер, оканчивающийся на `0000`, имитирует отсутствие аккаунта.

Стенд не подключён к основной странице и не попадает в `dist/`. Проверка на стенде не подтверждает реальную доставку в MAX.
